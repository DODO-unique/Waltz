SCENARIO: We have **framework** and **user**

1. I create a list of operations. Each ticket performs one operation
2. A ticket contains:
   1. unique identification (ID)
   2. operation flag/enum
   3. payload

One the user side of things, we create a listener class.
When user user inttiates this listener class, they get to use our decorator on that instance-
The decorator takes a mandatory enum argument. This argument registers the relevant enum in the instance's memory.
The function the user provides under this decorator must return what the decorator demands.
```py
# How it looks for the user:

listener = Listener()

TicketBus.subscribe(listener)

@listener.intiate("OPERATION_FLAG")
async def func(ticket: TicketType):
    do = "something"
    return do
```
In recent versions we would ask the users to use the internal ENUM to pass more accurate values:

```py
@listener.initiate(TicketEnum.OPERATION_FLAG)
```

In case anything goes wrong, the wrapper can handle the errors and raise a framework specific exception for user convenience

When a listener instance is generated by the user, they must subscribe to a relay service called TicketBus— for subscription, you pass it a trigger function object (which would be a method to the Listener class)

The ticket bus (a RPC bus) stores subscribed listeners in a set.

When the framework raises a request ticket the Bus takes the listeners triggers and calls them all by passing them the ticket.
The triggers, now active, take the ticket operation info from the ticket and check the registry we created earlier.
When it sees a relevant enum, it calls the function object and triggers relevant decorator function.

Now, the function runs and returns a payload.

Now, Caveats came in, knocking on the door because why not.
Designing the decorator has been, in itself, very intense.
There are two major problems:
1. How to seperate functions? Answer: You don't seperate functions. You apply the same rule to all of them as a 'request', not what kind of request it is. The decorator needs to stay dumb. Follow-Up: Which layer do we sperate- answered already.
2. How do we invoke this internally?
    Answer: This is a very neat question.
    Technically, when a simple decorator is designed, fundamentally, the user function is the argument of the decorator function. 
    In the same sense, technologically, the wrapper is the state you'd have a function in when you are calling it- the user function is when you are defining what you called.
    I know that was complicated so I have a scenario:
```py
def decorator(user_func):

    def wrapper(*args, **kwargs):
        # do something before
        user_func()
        # do something after
    return wrapper
```

Say that's the decorator.
Now, let's look at how a user would use that decorator:
```py
@decorator
def foo():
    # do something
```

But that does not work until you call `foo()`
So you do:
```py
foo(a, b)
```

Now- this is the most important point:
OBSERVATION: 
    `foo(a, b)` (The Call) is resolved as `wrapper(*args, **kwargs)`
    `def foo() {}` (The Definition) acts as `user_func()`

DERIVATION:
    What happens is, when you define `@decorator`, python takes following funciton and wraps it around the caller, so you have: `decorator(foo)`
    then OVERWRITES the function object; so in our case: 
    `foo = decorator(foo)` 
    What happened? `foo` is now `wrapper`
    
    BUT PAUSE

    the innocent `user_func()` laying inside wrapper is still the old `foo()` because that was the context when wrapper was captured before returning.

    So, you have:
        Defined `foo()` is the user function. Inside. A boy.
        The calling `foo()` is the wrapper. Outside. A man.

```py
class Listeners:

    def __init__(self) -> None:
        self.registry: dict[TicketEnum, Callable[..., dict[str, str]]] = {}
    
    def decorator(self, record_enum: TicketEnum):

        def actual_decorator(user_func: Callable[..., dict[str, str]]) -> Callable[[None], dict[str, str]]:
            def wrapper(payload: None) -> dict[str, str]:
                x: dict[str, str] = user_func(payload)
                return x
            if record_enum not in self.registry:
                self.registry[record_enum] = wrapper
            return wrapper
        return actual_decorator

    def trigger(self, ticket: TicketType):
        if ticket.type in self.registry:
            result = self.registry[ticket.type](ticket.payload)
            return result
        else:
            ValueError("Relevant ticket not registered")
```
